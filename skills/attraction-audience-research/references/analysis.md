# 内容分析、反例与报告

先用仓库 CORE.md 的命令导入、validate、analyze。只有验证通过才能把结果作为完整交付；部分失败也保留并说明影响。计数由 Python 完成，模型负责解释与有证据的标注。

## 解释顺序

1. 报告样本漏斗：检索候选→作者/评论门槛→实际核对→正例/反例/未知→主样本。说明作者数量与同作者上限。
2. 对每帖给平台评论数、实际捕获条数、一级、楼中楼、作者回复以及 N/K/F。分母不同的比率不混用。成人目标排除明确未成年后仍包含年龄未知者。
3. 分主题、粉丝档、格式和采集深度比较。等帖子权重、等作者权重与合并已查样本比率回答不同问题，不能无说明替代。重复用户没有跨库标识时不做跨库独立人数统计。
4. 正反例同时解释：同样健身或车辆主题，主体、生活语境、文案问题、可参与话题有何不同；不足以解释的差异保留未知，不事后编故事。

## 内容特征

逐媒体标注 role=cover/later_image/video_segment，主体为人物、人物+自然、人物+生活、物品等；构图记录景别、人物占比、视角、环境关系。看过封面不能代表整组，看过片段不能代表全片。视觉标注需来源、版本、审核状态。

本地保存平台 tag 与正文话题，区分作者自述、旁观者描述和无关引流。文案分析问题形式、情景细节、开放讨论入口、是否只展示；不要把单个热词当效果原因。评论意图区分人身欣赏、实用咨询、共同兴趣、争论、广告和回复他人。私人消息只能用自有账号授权聚合结果，公开“私了”不是实际私聊。

## 女性聚合画像

只有明确披露者进入对应统计；年龄不足不得用职业/学校补全。公开反复表达的兴趣可作稳定兴趣，一次话题互动单列；本人穿搭呈现不等于喜欢什么类型男性。群体按兴趣组织，例如运动训练、户外路线、器材/驾驶、日常生活、娱乐创作，不能把它们当固定“女性类型”。

年龄、兴趣小格不足 10 人不输出细分数；未知占比必须保留。社区 v1 不接收逐人画像或稀疏画像表，详细聚合在本地报告查看。

## 输出与验证假设

`reporting.py` 生成可离线打开的内容分析 HTML，其中高女性案例模式会突出通过初筛案例；用 community HTML 或完整 analysis.notes 对照全部反例和未知，不能只展示筛选后结果。

每条建议附证据强弱、可复现场景、制作成本和下一步实验。例如在自己的账号、相近时间窗比较两种文案，固定主题与拍摄成本，观察有效评论与可归因主动私聊。探索性相关性不能写成“这样拍一定吸引女性”。

归档报告、分析 JSON、输入清单、统计口径与生成脚本版本。HTML 的数字必须来自同一版本分析，不能手动写一套不同分母。
